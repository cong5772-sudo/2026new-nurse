# 신규간호사 발령 유지관리 시스템

해운대백병원 간호국 신규간호사 발령·사직 현황 대시보드입니다.
구글 시트 **[26신규명단]**을 원본으로 하며, PC와 휴대폰 어디서나 같은 주소로 볼 수 있습니다.

- **발령현황**: 누적 발령인원, 발령 회차, 발령일자별 인원, 부서 구분별 세부부서 발령표
- **사직분석**: 기간별 조회(현재·연도·반기·분기·월, 여러 구간 동시 선택), 부서 구분별·발령일자별 사직율, 사직 발생 시기, 생존곡선, AI 역량검사·석차·성별·사유별 분석
- **부서별 사직**: 부서별 사직 현황과 전년도(2개 연도) 사직율 비교, 위험 신호

## 구성

```
docs/index.html            대시보드 화면 (GitHub Pages가 이 폴더를 게시)
docs/config.js             연결 주소·목표 사직율·전년도 전체 수치 설정
apps-script/DashboardApi.gs 구글 시트를 읽어 집계값만 내보내는 Apps Script
```

데이터 흐름: **구글 시트 → Apps Script(집계) → 대시보드**

원본 시트는 비공개로 그대로 둡니다. Apps Script가 시트를 읽어 **부서·회차·구분별 인원수와 사직율 같은 집계값만** 내보내고, 성명·사원번호·출신학교는 내보내지 않습니다.

## 처음 설치 (한 번만)

### 1단계. 집계 API 만들기 (Apps Script)

1. [script.google.com](https://script.google.com)에 시트 소유 계정으로 로그인 → **새 프로젝트**
2. 프로젝트 이름을 `신규간호사 대시보드 API`로 바꿉니다.
3. 기본 `Code.gs` 내용을 모두 지우고 `apps-script/DashboardApi.gs` 내용을 붙여넣은 뒤 저장(Ctrl+S)합니다.
4. 위쪽 함수 선택에서 **`testDashboardData`**를 고르고 **실행**을 누릅니다.
   - 처음에는 권한 승인 창이 뜹니다. 계정 선택 → *고급* → *(안전하지 않음)으로 이동* → 허용
   - 아래 실행 로그에 `발령 151명 / 사직 38명 …`처럼 나오면 정상입니다.
5. 오른쪽 위 **배포 → 새 배포** → 톱니바퀴에서 **웹 앱** 선택
   - 실행 계정: **나**
   - 액세스 권한: **모든 사용자**
6. **배포**를 누르고, 표시되는 **웹 앱 URL**(끝이 `/exec`)을 복사합니다.

> 시트의 기존 Apps Script(사직정보 자동화)와 섞이지 않도록 **별도 프로젝트**로 만듭니다.

### 2단계. 대시보드에 주소 넣기

GitHub 저장소에서 `docs/config.js`를 열고 연필(편집) 아이콘을 누른 뒤 `API_URL`에 붙여넣고 저장(Commit changes)합니다.

```js
API_URL: 'https://script.google.com/macros/s/……/exec',
```

### 3단계. GitHub Pages 켜기

1. 저장소 **Settings → Pages**
2. Source: **Deploy from a branch**, Branch: **main**, 폴더: **/docs** → Save
3. 1~2분 뒤 주소가 생깁니다: `https://cong5772-sudo.github.io/2026new-nurse/`

> 비공개 저장소의 GitHub Pages는 유료 플랜에서만 쓸 수 있습니다. 무료 계정이면 **Settings → General → Danger Zone → Change visibility**에서 저장소를 공개로 바꿔야 합니다. 공개하기 전에 아래 *공개 전 확인*을 먼저 해 주세요.

### 4단계. 휴대폰 홈 화면에 추가

- 아이폰(사파리): 공유 버튼 → **홈 화면에 추가**
- 안드로이드(크롬): ⋮ 메뉴 → **홈 화면에 추가**

## 공개 전 확인

- 이 저장소의 예전 버전(`assets/live-sync.js`)에는 **이전 Apps Script 주소**가 들어 있습니다. 그 주소는 성명은 빼고 부서·발령일·사직일·출신학교·석차 같은 **개인 단위 기록**을 돌려주는 방식입니다. 저장소를 공개하기 전에 그 Apps Script 프로젝트에서 **배포 → 배포 관리 → 해당 배포 보관(Archive)**으로 꺼 주세요.
- 대시보드 주소는 링크가 있으면 누구나 볼 수 있습니다. 검색엔진에는 노출되지 않도록 설정되어 있습니다(`noindex`).
- 부서당 신규간호사 수가 적어, 내부 사정을 아는 사람은 부서·회차별 사직 인원으로 개인을 짐작할 수 있습니다. 간호국 공개 범위 기준에 맞는지 확인해 주세요.

## 운영

| 하고 싶은 일 | 방법 |
|---|---|
| 시트 수정 내용 반영 | 자동입니다. Apps Script가 응답을 5분간 저장해 두므로 **최대 5분** 뒤 반영됩니다. |
| 시트 수정을 바로 반영 | Apps Script 편집기에서 `clearDashboardCache` 실행 |
| 목표 사직율, 전년도 전체 발령인원·사직율 변경 | `docs/config.js` 수정 |
| 부서별 전년도 사직율 | 시트 **[부서별 발령/사직]**의 `2025년 사직율`·`2024년 사직율` 열을 고치면 자동 반영됩니다. 중환자·수술회복·응급 값도 이 열에 넣으면 표시됩니다. |
| 부서 추가·구분 변경 | `DashboardApi.gs`의 `GROUPS` 수정 → 저장 → **배포 → 배포 관리 → 연필 → 버전: 새 버전 → 배포** (주소는 그대로 유지) |
| 내년 명단 탭으로 전환 (예: 27신규명단) | `DashboardApi.gs`의 `ROSTER_SHEET` 수정 후 위와 같이 새 버전 배포. 화면의 연도 표기(올해·전년도)는 발령일자를 보고 자동으로 바뀝니다. |

화면 오른쪽 위 기준일 옆 점의 색은 데이터 상태를 나타냅니다.

- 초록: 최신 데이터
- 노랑: 저장본을 먼저 보여주고 최신 데이터를 받는 중
- 빨강: 연결 실패로 저장본을 표시 중 (점에 마우스를 올리면 이유가 나옵니다)
